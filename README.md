## 3. 우리가 만든 것

**팬덤이 '어디·언제'를 정하면, 유미가 '무엇을 먹고 어떻게 예약할지'를 끝낸다.** 한국어 · English · 日本語 · 中文

| 기능 | 하는 일 |
|---|---|
| **동선** | 공연장·생카 + 시간 + 인원 + 관광객 필터(외국어·해외 결제·할랄·비건·단체석) → 그 시간에 열고 바로 예약되는 곳 |
| **버디 AI** | "고척스카이돔 공연 끝나고 4명", "정국이 간 맛집" → 찾기·사장님 동시 문의·예약 |
| **같이 밥 먹기 (밥팟)** | 식당 고르고 "4명 모이면 예약" + 내 소개 → X 초대 링크 → 인원이 차면 유미로 **자동 예약** |
| **해외 번호 예약** | 이메일·해외 번호 → 유미 사장님 앱·POS 알림 → 사장님 수락 |
| **택시·주문 카드** | 한국어 주소·메뉴를 크게, 네이버·카카오·구글 지도로 바로 |
| **매장 태그 · 포카 교환** | NFC/QR 태그 → 자동 입장 → 팝업에서 "정국 포카 가진 사람 1명" 매칭 → 가게 안 대면 교환 |
| **성지 지도 · 생카** | 스타 방문 가게(뉴스 출처) + X 공지 링크로 생카 등록 |
| **사장님 수요 리포트** | "예약되면 좋겠어요"가 언어별로 쌓이는 화면 — 실패한 예약이 영업사원이 된다 |

## 4. 어떻게 동작하나 — 찾기 → 확인 → 예약 요청

| 단계 | 헤이유미 API |
|---|---|
| 찾기 | `places/nearby` (`open_at`, `reservation_channel=yumi`, `foreigner_friendly`, `payment_methods`, `muslim_friendly`, `dietary`, `recommended_for`) · `associated_with`(성지) · `regions` |
| 확인 | `places/{id}` (메뉴·사진·외국어·결제) · `live-status` 사장님 4명께 동시에 "지금 4명 돼요?" |
| 예약 요청 | `reservations` (해외 번호·이메일, 밥팟은 목표 인원 도달 시 서버가 1회만 요청) → `reservations/{id}` 상태 확인 |
| 현장 | 매장 태그 5분 회전 서명 토큰 → 입장 확인 · 포카 교환 |

## 5. 쓰는 장면

1. 버디에게 "고척스카이돔 공연 끝나고 4명" → 21:30에 열고 바로 예약되는 4곳
2. **트친이랑 같이 밥 먹기** → 어다리횟집 선택, "4명 모이면 예약", "도쿄에서 온 아미, 정국 최애" → X에 초대
3. 트친 3명이 링크로 참여 → 4명이 차는 순간 유미로 예약 요청 → 사장님 수락 → "예약 확정"
4. 택시 카드를 기사님께 보여주고 이동
5. 가게 카운터 태그 → 포카 교환 팝업 → 같은 가게 팬과 대면 교환
6. 사장님 앱엔 예약 알림 + 해외 팬 수요

## 6. 무엇이 다른가

**예약이 된다는 건 더 이상 차별점이 아니다. 우리는 팬의 날짜와 장소에서 시작한다.**
공연 끝나는 시간에 KSPO돔·고양종합운동장·인스파이어 아레나 반경 5km 안 유미 예약 가능 파트너는 **0곳**(고척·홍대는 4곳) — 수요는 있는데 공급이 비어 있다 = 헤이유미가 영업할 곳 지도. (헤이유미 API 직접 조회, 2026.10.17 · 10.24 18:00·21:30 기준)

## 7. 만들면서 배운 것

- REST `nearby`의 `open_at` + `reservation_channel=yumi` 조합으로 "그 시간에 예약되는 곳"이 한 번에 나온다. 파트너가 없으면 `reservationFallback`으로 알려줘서 그대로 수요 리포트로 연결했다.
- REST에는 `group_friendly` 파라미터가 없어 `recommended_for=group_dining`으로 대신했다.
- 공연장(KSPO·고양·인스파이어)은 `regions`로 안 잡혀서 좌표를 직접 넣었다.
- 샌드박스(`X-Map3-Sandbox`)로 사장님께 알림 없이 예약 확정까지 전 과정을 검증했다.

## 데이터

- `.data/app.db` — SQLite (Node 내장 `node:sqlite`). 테이블: users, demand, logs, log_likes, events, presence, trades, offers, reports, blocks, meets, meet_members.
- 예약의 이름·전화번호·이메일은 서버에 저장하지 않고 헤이유미로만 전달한다. 밥팟 방장의 예약 연락처만 자동 예약 요청 때까지 보관했다가 요청 즉시 지운다. 내 예약 목록은 기기(localStorage)에만 있다.
- 매장 입장 기록은 2시간, 교환 글은 24시간 뒤 자동 삭제. 계정 삭제 시 그 계정의 모든 데이터가 지워진다.

## 보안 장치

- 로그인: scrypt 비밀번호 + HMAC 서명 HttpOnly 세션 쿠키. 쓰기 API는 모두 로그인 필요.
- 요청 제한: 로그인 시도 10회/10분, 실시간 문의 4회/분(같은 가게 2분 1회), 버디 “지금” 동시 문의 2회/5분 등.
- 매장 태그: 5분마다 바뀌는 서명 토큰(`/tag/<매장>?t=…`), 사장님 앱 QR이 자동 갱신.
- 콘텐츠 필터: 연락처·외부 링크·욕설 차단, 교환 글은 송금·택배 문구도 차단. 신고 3건이면 자동 숨김. 차단한 사람의 글은 안 보임.
- 교환 완료는 양쪽 모두 확인해야 닫힘. 확인 코드는 교환 당사자 두 명만 볼 수 있음.

## 출시 전 남은 일
